# База элементов и рецептов

Контент игры лежит в `content/` и не смешивается с кодом. Чтобы добавить элемент или рецепт, достаточно отредактировать JSON и тексты: движок алхимии менять не нужно.

```
content/
├─ categories.json          категории и их порядок в списке
├─ elements/<блок>.json     элементы (файлы можно делить по смыслу)
├─ recipes/<блок>.json      рецепты
└─ locales/ru/
   ├─ elements.json         названия и описания элементов
   ├─ categories.json       названия категорий
   └─ ui.json               тексты интерфейса
assets/elements/<id>.svg    иллюстрации
```

## Элемент

```json
{ "id": "steam", "category": "matter", "art": "elements/steam.svg" }
```

| Поле | Обязательно | Смысл |
|---|---|---|
| `id` | да | Стабильный идентификатор: `a–z`, `0–9`, `_`, начинается с буквы. **После выпуска не меняется**: на него ссылаются сохранения. |
| `category` | да | Категория из `categories.json`. |
| `art` | да | Путь к SVG относительно `assets/`. |
| `starting` | нет | Начальный элемент: доступен с первого запуска. |
| `secret` | нет | Секретный: не входит в отображаемое «всего», пока не найден. |
| `final` | нет | Из элемента намеренно ничего не создаётся (иначе проверка выдаст предупреждение). |

Название и описание задаются в `content/locales/ru/elements.json` по `id`.

## Рецепт

```json
{ "in": ["water", "fire"], "out": "steam" }
{ "in": ["mercury", "sulfur"], "out": "cinnabar", "ordered": true }
```

- `in` — ровно два ID. Можно соединить элемент сам с собой (`["water", "water"]`).
- `out` — ID результата.
- `ordered` — важен ли порядок (по умолчанию нет).
- Несколько рецептов для одного результата — несколько записей с одинаковым `out` (в базе так получаются Дождь и Песок).

## Правила соединения

Выбраны самые простые и предсказуемые варианты.

1. **Одна пара — один результат.** Одинаковая комбинация всегда даёт один и тот же элемент. Случайности нет.
2. **Порядок по умолчанию не важен:** «Вода + Огонь» и «Огонь + Вода» — один рецепт.
3. **Упорядоченный рецепт** (`ordered: true`): первым считается элемент, который переносят или выбирают первым; вторым — тот, на который его кладут или который выбирают вторым. Для одной пары нельзя одновременно задать упорядоченный и неупорядоченный рецепт. В текущей базе упорядоченных рецептов нет: возможность заложена в движок и покрыта тестами.
4. **При успехе** участники исчезают со стола; элементы из списка бесконечны и не расходуются, начальные доступны всегда.
   - **Новое открытие:** результат появляется на месте цели с анимацией открытия и уведомлением «Новое открытие».
   - **Результат уже открыт:** повторный экземпляр на стол не кладётся (элемент есть в списке), анимации открытия нет. Уведомление «Вы уже знаете этот рецепт».
   - **Результат уже открыт, но рецепт новый:** экземпляр тоже не создаётся, рецепт записывается в прогресс. Уведомление «Найден альтернативный рецепт».
5. **При неудаче** ничего не теряется: элементы остаются на столе, игрок видит пояснение.
6. **Уникальные открытия** — открытые элементы, кроме начальных. Повторное получение известного элемента счётчик не увеличивает. Найденные рецепты запоминаются при любом успешном соединении, в том числе когда результат уже открыт.
7. **«Всего»** — все неначальные несекретные элементы плюс уже найденные секретные.

## Проверка базы

```bash
npm run content:check
```

Выполняется в `npm run check` и в unit-тестах. **Ошибки** (сборка не проходит):

- дубликаты элементов и рецептов, в том числе с переставленными входами;
- конфликтующие рецепты (одна пара — разные результаты), конфликт упорядоченного и неупорядоченного рецепта;
- ссылки на несуществующие элементы во входах и результатах;
- элемент без рецептов, если он не начальный;
- недостижимые элементы, включая замкнутые циклы без пути от начальных;
- некорректные начальные элементы: их нет совсем, начальный элемент секретный или создаётся рецептом;
- неверный формат `id`, неизвестная категория;
- нет названия или описания, нет файла иллюстрации.

**Предупреждения:**

- элемент-тупик без пометки `final`;
- `final` у элемента, который используется в рецептах;
- результат совпадает с одним из входов.

Отчёт также показывает глубину цепочек — сколько соединений нужно до каждого элемента.

- **Категории:** Первоначала, Природа, Вещества, Алхимия.
